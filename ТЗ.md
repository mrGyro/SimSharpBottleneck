# SimSharp Demo Project  
## Bottleneck Detection in a Manufacturing Line (Discrete-Event Simulation)

### 🎯 Goal
Build a **discrete-event simulation** using **SimSharp** that demonstrates:
- how production systems behave under constraints,
- how bottlenecks emerge and migrate,
- how a small local improvement can unexpectedly worsen the whole system.

The project should be suitable for:
- a **LinkedIn post** (graphs + short animation/video),
- showcasing practical SimSharp knowledge to employers,
- exploring manufacturing / operations / systems simulation.

---

## 🧠 Key Concepts Demonstrated
- Discrete-event simulation
- Resource contention & queues
- Bottleneck analysis
- Throughput vs Lead Time tradeoff
- System instability from small parameter changes

---

## 🏭 System Description

The system simulates a **linear production line** consisting of several stations.

### Stations
1. Cutting
2. Assembly
3. Testing
4. Packaging

Each station:
- has a limited number of machines (resources),
- processes items one by one,
- may have an input buffer (queue),
- has a stochastic processing time.

---

## 🔁 Entity Flow

- Items arrive into the system from a source.
- Each item passes through all stations sequentially.
- After Packaging, the item leaves the system.
- Metrics are collected throughout the simulation.

---

## ⏱ Time Model

- Simulation time unit: **minutes**
- Simulation horizon: **e.g. 8 hours (480 minutes)** or configurable
- Item arrival process: stochastic (e.g. exponential inter-arrival time)

---

## 📦 Core Entities

### 1. Item
Represents a single product moving through the system.

**Attributes:**
- Id
- CreationTime
- CompletionTime

---

### 2. Station
Represents a processing step.

**Attributes:**
- Name
- Resource (SimSharp.Resource)
- MeanProcessingTime
- InputQueueLength (derived)
- BusyTime (for utilization)

**Behavior:**
- Request resource
- Process item
- Release resource

---

### 3. ProductionLine
Orchestrates stations and item flow.

**Responsibilities:**
- Create stations
- Route items between stations
- Track system-level metrics

---

## 📊 Metrics to Collect

### Per Station
- Utilization (%)
- Average queue length
- Number of processed items

### System-Level
- Throughput (items/hour)
- Average Lead Time (time in system)
- Work In Progress (WIP)
- Max queue length observed

All metrics should be exportable to **CSV** for plotting.

---

## ⚙️ Simulation Scenarios

### Scenario A: Baseline
- Default processing times
- Balanced but constrained system

### Scenario B: Local Optimization
- Reduce processing time of ONE station by ~5–10%
- Observe:
  - queue growth
  - lead time change
  - throughput change
  - bottleneck migration

### Scenario C: Structural Fix
- Add buffer or resource to true bottleneck
- Compare metrics with Scenario B

## 🧩 Implementation Notes (for Copilot)

- Use `Environment` as the simulation clock.
- Use `Resource` for machines.
- Each station should expose a `Process(Item item)` coroutine.
- Item generation should run as a separate process.
- Prefer **yield return env.Timeout(...)** over manual time tracking.
- Avoid shared state where possible; collect metrics centrally.

## 🧠 Expected Insights

- Improving a non-bottleneck station does not improve throughput
- Small local optimizations can increase WIP and lead time
- True system improvements require bottleneck-focused changes
